# Terminology

The words to use in user-facing text of the Restate UI: labels, headings, dialogs, toasts, errors, empty states and code snippets shown to users. They match the Restate admin API, the SQL introspection tables, the CLI, the SDKs, the Terraform provider and docs.restate.dev, so a word means the same thing everywhere. Restate Cloud adds terms of its own (accounts, API keys, roles) on top of these.

- **Use**: the word for UI copy.
- **Avoid**: words seen for the same thing that clash with another surface. Where an avoided word is the literal name of a field, column, flag or config key, it stays fine for naming that.
- **Where** lists the surfaces that already use the term:
  - **UI**: this UI. **Cloud**: the Restate Cloud console.
  - **API**: the admin API. **SQL**: the introspection tables (`restate sql`, `/query`). **Config**: server configuration keys.
  - **CLI**: `restate`. **SDK**: the SDKs. **TF**: the Terraform provider `restatedev/restate`. **Docs**: docs.restate.dev.

Casing and tone follow the Voice & Content Strategy in [`DESIGN.md`](DESIGN.md): sentence case everywhere. Service type names (Basic Service, Virtual Object, Workflow) are names and stay capitalized. Code identifiers may follow older names (`connect`, `call`); never show them to users. Before renaming a term, read [Renaming a term](#renaming-a-term).

## Invoking

| Use                      | Meaning                                                                                                                                          | Where                                                              | Avoid                                                       |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------ | ----------------------------------------------------------- |
| invoke, invocation       | Send a request to a handler through Restate. Each request is one invocation with an `inv_…` ID                                                   | API `/invocations`, CLI, Docs, UI, Cloud                           | "run", "trigger", "execute", and "call" as the general verb |
| call                     | An invocation whose caller waits for the result                                                                                                  | ingress `/restate/call/…`, SDK, journal "Call", UI playground mode | "call" in titles and role labels ("Call services")          |
| send                     | An invocation whose caller doesn't wait; it gets the invocation ID back. Docs call it sending a message ("Sending messages", "Delayed messages") | ingress `/restate/send/…`, SDK, journal, Docs, UI playground mode  | "fire-and-forget" as a label                                |
| ingress                  | The HTTP entry point (port 8080) that accepts invocations from outside Restate                                                                   | API, Config, CLI, Docs, TF                                         |                                                             |
| Playground               | The page that invokes a handler from a form                                                                                                      | UI, Docs                                                           | "Explore", "Try it"                                         |
| public / private service | Public: the ingress accepts invocations of it. Private: only other services can invoke it. Handlers can be public or private too                 | API `public`, CLI visibility, UI "Access"                          |                                                             |

## Invocation lifecycle

Status labels: New, Scheduled, Ready, Backing off, Yielded, Running, Suspended, Paused, Succeeded, Failed, Killed, Cancelled. New means the invocation hasn't started yet (the UI said Pending before 1.1.9; the CLI and the deprecated SQL `status` column still say `pending`). Yielded means the invocation gave its turn back, for example under memory pressure, and waits to run again. SQL `effective_status` values are lowercase (`new`, `backing-off`, `yielded`). Avoid "Pending" for New, "Backing-off" as a label (`backing-off` is the value), "Retrying" as a status (the journal's Retrying row is an event), "canceled", and "Finished" for a status (`finished` is the stage of all four end states).

| Use            | Meaning                                                                                                                      | Where                                                | Avoid                                                                 |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- | --------------------------------------------------------------------- |
| in-flight      | Not finished and not scheduled: running, held up or suspended. The sidebar's In-flight list                                  | UI "In-flight", API, CLI, Docs                       | "inflight"; "in-flight" for counts that include scheduled invocations |
| unfinished     | Every status except Succeeded, Failed, Killed and Cancelled, scheduled included. Health warnings compare against it          | UI health warnings                                   | "in-flight" for this set                                              |
| Cancel         | Stop gracefully. The handler gets a cancellation error and can run compensations                                             | API, CLI `cancel`, Docs, UI                          | "abort", "stop"                                                       |
| Kill           | Stop at once, without compensations. A last resort                                                                           | API, CLI `kill`, Docs, UI                            |                                                                       |
| Pause, Resume  | Pause holds an invocation until someone resumes it. Resume also wakes suspended invocations and retries backing-off ones now | API, CLI, Docs, UI                                   |                                                                       |
| Retry now      | UI name for resuming a backing-off invocation now (API and CLI: resume)                                                      | UI, Docs changelog                                   | "Retry" alone                                                         |
| Restart as new | Run a completed invocation again as a new invocation, from the start or from a journal entry                                 | API `restart-as-new`, CLI `restart-as-new`, Docs, UI |                                                                       |
| Purge          | Delete a completed invocation's result, journal and metadata. Can't be undone                                                | API, CLI `purge`, Docs, UI                           | "delete invocation" (deprecated API)                                  |

## Journal

| Use     | Meaning                                                                                                                                                                                | Where                                           | Avoid                               |
| ------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------- | ----------------------------------- |
| journal | The record of what an invocation did, replayed after a failure                                                                                                                         | API, CLI, Docs, UI                              | "execution log"                     |
| entry   | One row of the journal. Kinds: command (what the handler did: Call, Run, Sleep…) and notification (a command's result, or a signal)                                                    | SQL `sys_journal`, CLI "Call command", Docs, UI | "action" or "step" for a row        |
| event   | Something recorded about an invocation that isn't a journal entry, such as a transient error or a pause                                                                                | SQL `sys_journal_events`, UI                    |                                     |
| action  | A durable step that Restate records and Restate Cloud bills: an invocation's start and result, and each call through the Restate context (run, sleep, call, state, promise, awakeable) | Docs (Actions page), Cloud usage                | for a journal row (that's an entry) |

## Awakeables, signals, promises

These follow the docs' own rules (docs-restate `AGENTS.md`, "Durable coordination terminology").

| Use                       | Meaning                                                                                                                                                                       | Where                                                                               | Avoid                                               |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- | --------------------------------------------------- |
| awakeable                 | A one-shot signal with a generated ID, completed through the SDK or the HTTP API                                                                                              | ingress `/restate/awakeables/<id>/resolve` and `/reject`, SDK, Docs, UI, Cloud role | "callback", "task token" (patterns, not primitives) |
| signal                    | A repeatable primitive addressed by invocation ID and signal name                                                                                                             | API, CLI `invocations signal`, Docs, UI                                             | "event", "channel", "stream"                        |
| workflow promise          | A named promise of one workflow, resolved once and read many times                                                                                                            | Docs, SQL `sys_promise`, SDK `ctx.promise()`, UI "Pending promises"                 |                                                     |
| durable promise           | Plain-language umbrella for a promise that survives crashes and restarts, and the SDK type of a workflow promise (`DurablePromise`). Name the exact primitive when it matters | Docs, SDK                                                                           |                                                     |
| complete, resolve, reject | Complete means resolve (with a value) or reject (with an error)                                                                                                               | ingress `/resolve` `/reject`, CLI, Cloud role "Complete awakeables", UI             | "fail", "fulfill", "trigger"                        |

## Renaming a term

1. **Public surfaces.** A term is public once it appears in the admin API, SQL table and column names, server configuration keys, the CLI, Terraform, an SDK message or env var, or the docs. Docs click paths such as "Overview > Register services" count.
2. **Search before you rename.** Look for the old word in:
   - restate (admin API, SQL tables, configuration, CLI)
   - copies generated from restate: the docs' `schemas/openapi-admin.json`, `references/server-config.mdx` and `references/sql-introspection.mdx`, and this repo's `admin-api-spec`. Rename in restate first, then regenerate them
   - the SDKs, including sdk-shared-core (env vars, log lines, doc comments, `--help` text)
   - docs-restate
   - terraform-provider-restate and deploy tooling such as restate-operator and cdk
   - templates, examples and skills that quote the UI
   - this repo. Restate Cloud reuses this UI and quotes many of these terms, so rename there in the same change.
3. **Everywhere at once, or not at all.** Rename the term everywhere in one coordinated change with its owners, or keep it. To tell two similar things apart, add a qualifier ("Management API key"), not a new word.
4. **Keep old links working.** Redirect old routes and anchors: docs and SDK errors link to them.
5. **Update this file in the same PR.**
